Away queue: one week, nobody reachable

A person sets tasks, leaves the laptop on, and is out of contact for a week. Every decision a person must make happens before they leave.

The same flow in words

Numbers match the step tags in the picture.

Before leaving (the person is present)

  1. Write the queue. Each job has a brief, a folder, a model, checks and approval ticks.
  2. Pre-flight. Check that the machine is ready: power, no sleep, updates, disk, sign-in, version, self-start. If it is not ready, fix it and run pre-flight again.
  3. Stall forecast. List which jobs will stop at a ticked item. For each one, untick it, answer it now, or accept that it waits.
  4. Approve the queue. It is now frozen. This is the last act that needs a person.

While away (the runner alone, in a loop)

Nothing asks. Nothing in an editor is closed or reloaded. Every action is logged.

  1. Pick the next ready job: its dependencies are done and it is not set aside. If nothing is ready, write the report and wait.
  2. Gates. All must pass, otherwise wait and re-check: an agent slot is free; load is OK (memory, GPU, renders); the usage allowance is OK (normal, then economy, then hold until the reset).
  3. Prepare the job's own copy (its own branch) and its rules file (checklist, floor, fence).
  4. Start a headless Claude session with the job's model, effort and rules.
  5. The session ends one of five ways:
    • Finished: the runner runs the checks. Pass: the job is done, back to step 5. First fail: retry once with the failure, back to step 8. Second fail: set aside.
    • Reached something outside what was approved: set aside with the exact question. Dependants wait. Back to step 5.
    • Usage limit: hold until the reset, then continue the same session (back to step 8).
    • Time or budget cap: end the run and set the job aside.
    • Context grew large: write a handover and continue in a fresh session (back to step 8).

Side path. If the machine restarts or the runner crashes, the runner starts itself and continues at step 5; an interrupted job resumes by its session id.

On return (the person is present)

  1. Read the report: done, set aside (each with its question), failed, spend, timeline, branches.
  2. Answer the set-aside jobs by typed command. They resume, back into the loop at step 5.
  3. Review and merge the branches yourself. Open any session as an editor tab.
